# BioD Dashboard v2

기존 CRO Excel 파서와 화면을 유지하면서 의사결정 분석 기능을 추가한 버전입니다.
Candidate Analysis와 BioD Report를 별도 탭으로 제공합니다.

## 실행

이 폴더의 `Dash.bat`를 더블 클릭합니다. 기존 런처의 Python 경로를 사용합니다.
다른 Python 환경에서는 다음과 같이 설치·실행합니다.

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

`app.py`, `biod_analysis.py`, `biod_ui.py`, `biod_mollim.py`, `biod_labels.py`, `biod_reporting.py`는 같은 폴더에 있어야 합니다.

## 사용

1. 기존처럼 몰림·Minerva·KIRAMS `.xlsx`를 업로드하고 표시 물질명을 지정합니다.
   몰림 파일은 `Compound`·`물질명`·`Test Article` 등의 명시적 물질명 열을 `Group`보다
   우선 사용합니다. 해당 열이 없으면 Group, 둘 다 없으면 기존처럼 시트명을 사용합니다.
   상단 제목 행과 물질명·시간 열의 병합 셀을 지원하며, 업로드 파일 요약에 선택한 물질명 열을 표시합니다.
   `AC-SK-001` 같은 물질 코드의 숫자는 시간점과 같아도 보존합니다.
   이름 끝의 `1h`, `(4h)`, `[48 hours]`처럼 시간 단위가 명시된 접미사만 제거합니다.
2. **Candidate Analysis** 탭에서 비교할 물질, 표적 장기,
   비교 장기, Reference를 선택합니다. 그룹은 파일 내용·CRO·원래 그룹명 기준으로 구분합니다.
   파일 이름이 같아도 내용이 다르면 별도 분석하며, 완전히 같은 파일의 중복 업로드는 제외합니다.
3. AUC는 기본적으로 표적·비교 장기 관측 구간의 겹치는 범위에서 계산합니다.
   필요하면 접힌 **세부 계산 설정**에서 AUC 방식과 실측 시간 범위를 선택합니다.
   0시간 가정 방식에서는 0h도 선택할 수 있습니다. 소수 단위 직접 입력은 제공하지 않습니다.
4. **후보 비교**에는 순위·AUC·비율과 물질명이 붙은 가로 막대그래프를 표시합니다.
   왼쪽은 표적 장기 AUC, 오른쪽은 비교 장기 AUC이며 물질 순서와 축 범위가 같습니다.
   각 막대에 실제 수치를 표시하고 Reference는 주황색과 이름으로 구분합니다.
   **장기 비율**은 장기·시점을 선택하면 `Tumor-Organ ratio`와 `Tumor-Organ ratio (AUC)`를
   각각 물질·장기 Mean/AUC·표적 Mean/AUC·비율의 4열로 표시합니다.
   일반 비율 **Excel 다운로드**는 선택한 장기의 전체 측정 시간을 포함합니다. 화면의 시점 필터는 다운로드 범위를 제한하지 않습니다.
   AUC 비율 Excel은 선택한 적분 구간의 표를 별도로 저장합니다.
   수치는 반올림 전 숫자로 저장하며 Settings 시트에 장기·시간·계산 방식과 출처를 포함합니다.
   **유지율·감소율**은 장기와 두 시점을 선택해 물질별 막대그래프와 유지율·감소율 3열 표로 확인합니다.
5. **Reference 비교**는 선택한 장기·시점의 후보 Mean·Reference Mean·증감률·p값·보정 p값·검정 결과를 표시합니다.
   `p값 (Student t-test)`는 양측 독립 Student t-test(등분산 가정), `보정 p값 (BH q)`는 Benjamini–Hochberg FDR로 명시합니다.
   **통계 검정 설정**에서 독립군·시험 조건을 확인하면 검정이 활성화됩니다.
   화면 필터는 표시만 바꾸며, BH 보정은 선택한 전체 물질·장기·시간의 유효 검정을 대상으로 유지합니다.
   원자료·표본 수·겉보기 반감기 등 상세 항목은 보고서에 보존합니다.
6. **📄 BioD Report** 탭은 분석 범위·주요 관찰·유지율·Reference 통계의 계산 기반 요약을 보여줍니다.
   선택적으로 검토 의견을 입력하고 **PDF** 또는 **Excel**을 직접 다운로드합니다.
   PDF는 요약과 핵심 표를 읽기 쉽게 배치하고, Excel은 결과 요약을 첫 시트에 두고 전체 시간 비율·상세 결과·원자료를 별도 시트에 저장합니다.
   PDF의 각 핵심 표는 최대 12행이며 전체 결과는 Excel에서 확인합니다. 한글 출력에는 맑은 고딕 또는 NanumGothic이 필요합니다.
   현재 요약은 계산 결과를 정해진 문장으로 정리한 것이며 외부 AI 해석은 포함하지 않습니다.
   AI 연동은 다음 단계로 미뤘으며 데이터 외부 전송은 없습니다.

## 분석 정의와 해석

- **AUC:** 선형 사다리꼴 적분. 관측 구간만, `0시간=첫 측정값`, `0시간=0` 중 선택합니다.
  실제 0시간 값이 있으면 그 값을 사용합니다. 0시간 가정을 적용해 0시간부터 적분하려면
  시작 시간을 0으로 지정합니다. 모든 비율·순위는 같은 시작·종료 구간을 사용합니다.
  관측 범위 안 경계는 선형 보간하며 마지막 관측 이후 외삽은 하지 않습니다.
  측정점이 2개 미만이거나 선택 구간을 포함하지 못하면 AUC를 미산출합니다.
- **Tumor-to-Organ:** 동일 파일·그룹·시점의 표적 평균 / 장기 평균입니다.
  개체별 비율의 평균이나 비율 곡선의 AUC가 아닙니다.
- **AUC ratio:** 동일 공통 구간의 표적 AUC / 장기 AUC입니다.
  분모가 0이거나 필요한 측정값이 없으면 비율을 미산출합니다.
- **Retention/Clearance:** 유지율=후기/초기×100, 감소율=100−유지율입니다.
  값이 증가하면 감소율은 음수입니다. 양수이며 감소하는 두 점에서
  `k_app=ln(초기/후기)/시간차`, `겉보기 반감기=ln(2)/k_app`을 계산합니다.
  두 점의 겉보기 감소 지표이며, 전신 청소율(CL) 또는 말단 반감기가 아닙니다.
- **Ranking:** 표적 AUC의 높은 순위 백분위와 비교 장기 AUC의 낮은 순위 백분위를
  1:1로 반영합니다. 선택 후보군 안에서의 탐색적 참고 순위입니다.
  동점은 같은 순위이고 후보 추가·제외에 따라 점수가 달라집니다.
  그래프는 이 순위대로 물질명을 표시하며, 두 장기의 AUC를 같은 축 범위로 비교합니다.
- **Reference:** 같은 장기·시간의 `(후보 평균/Reference 평균−1)×100`입니다.
  독립 개체 데이터가 각 군 2개 이상인 경우 등분산을 가정한 양측 Student t-test를 사용합니다.
  현재 선택한 전체 후보×장기×시간의 유효 p값에 BH FDR 보정을 적용합니다.
  AUC·비율의 통계 검정은 포함하지 않습니다. 군 독립성·시험 조건은 분석자가 확인해야 합니다.
  참고: [SciPy ttest_ind](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ttest_ind.html).
- **KIRAMS:** graph 시트의 평균값 입력으로 표시하며 SD·개체 검정은 계산하지 않습니다.
  다른 CRO도 개체 ID가 없거나 중복이면 검정을 제외하고 이유를 표시합니다.
  `rows`는 입력 행 수이며 동물 수를 뜻하지 않습니다.
- **원자료:** Excel 보고서의 표준화 원자료 시트에는 분석에 사용한 유효한 데이터를 포함합니다.
  시간/값의 결측·비수치·음수는 새 분석에서 제외하고 Quality 표에 수를 기록합니다.
  업로드 원본 Excel 전체를 보고서에 복사하지는 않습니다.
- **기존 3개 탭:** 기존 표시 그룹 기준 요약을 유지합니다. 서로 다른 파일의 같은 표시명이
  합쳐질 수 있으므로 파일별 비교·순위에는 새 분석 탭을 사용하세요.

## 검증

```powershell
python -m unittest -v test_biod_analysis test_biod_app test_biod_mollim test_biod_labels test_biod_reporting
```

합성 데이터로 수치 계산·통계 제외 조건·보고서 구조 및 Excel 업로드→화면 설정 변경을 검증합니다.
실제 CRO 원본 파일의 변형된 시트 구조에 대한 검증은 별도로 필요합니다.
